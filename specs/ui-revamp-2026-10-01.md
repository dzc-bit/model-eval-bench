# UI 改造规格书（2026-10-01，第二轮）

> 本文件是本轮三个视图改造的唯一作业依据。与 specs/claude-DESIGN.md（视觉系统）、
> specs/claude-ui.md（验收清单）冲突时，
> **以本文件为准**（它更新）。改完不更新 claude-DESIGN.md——那是有锁的视觉系统，本轮只动信息架构与交互。
>
> 用户原话拆解的四条不满（按优先级）：
> 1. 工作台：面板全堆一起、术语多（基线哈希/接线说明）、指引差、操作繁琐、结果提醒差；
> 2. 模型档案页：表单直出、操作逻辑差、UI 差；
> 3. 任务库：太朴素、原生下拉/输入框突兀、档位区分不明显；
> 4. 整体：有 Claude 壳子但质感不到位。

## 全局基调（所有视图共同遵守）

- 视觉 token 全部用 `css/tokens.css` 现有变量，**禁止新发明颜色**。档位语义色例外（见任务库节，来自官方色板）。
- 一屏内实心强调按钮最多 1 个（claude-ui.md §0）。卡片可点时不放同权重按钮。
- 正文行高 ≥1.6（CJK），控件行高 ≥1.45；所有可点目标 ≥28px 高（桌面）。
- 术语黑名单（界面正文禁止出现）：基线哈希、接线、评分度量、打分口径、沙箱根。这些内容要么删除，要么收进"详情"折叠。
- 数字、路径、哈希一律 `--font-mono` + tabular-nums。
- 每个视图的样式放**自己的新 CSS 文件**（见下），不再往 views.css 里加。选择器一律挂在视图根 class 下。

### 目标信息架构（桌面 ≥1080px 两栏，以下单列）

```
[题头条] 任务编号+标题（衬线大字）· 档位徽标 · 第 n 轮/共 m 次 · 沙箱状态一句话
         右侧：[查看改动(diff)] 一个次级按钮。路径/哈希/运行ID全部不出现。
[步骤条] ① 对话改代码 → ② 运行校验 → ③ 结果与下一轮；当前步高亮，已完成的打勾。
         点击步骤滚动到对应卡片（保留键盘可达）。取代现在的"跳转到"分段控件。
[主栏 60%]
  内置对话卡（视觉主角）：
    - 卡头：模型档案下拉（就放在这，原"本轮信息"里的选择器搬来）+ 对话状态
    - 消息流（含工具轮折叠、最终总结置顶——现状保留）
    - 粘性输入区：textarea + [发送]（主强调唯一）+ [发送当前轮提示词] 幽灵按钮
[侧栏 40%] 三张可折叠卡，默认展开状态：提示词=收起、沙箱=收起、校验=展开
  ① 任务与提示词卡：题目一段话简介（取任务 meta 的 goal/描述，只显示 3 行+展开）
     当前轮提示词：默认收起成一行「第 1 级提示词（症状级）· 1.2k 字」+ [发送到对话] [展开查看]
     原则：正文里永远不直接铺整段提示词全文。
  ② 沙箱卡：一行状态（就绪/已改动 n 个文件）+ [打开沙箱目录] [清空改动] [重建沙箱]
     「详情」折叠里才出现：沙箱路径、基线哈希、沙箱日志。改用"详情"而不是术语裸奔。
  ③ 校验卡：一句话说明（见文案表）+ [运行校验]（侧栏内唯一允许的强调按钮，G 键保留）
     校验中：进度态 + 可取消；校验完：结果横幅（通过=绿 tint 未过=红 tint）+ 总分 + 分组明细
     + [进入下一轮] 或机会用尽的说明。这是"结果提醒差"的正解：结果必须在这张卡里跳出来。
  ④ 本轮备注：一个可折叠小卡（textarea + 保存），元信息（开始时间/运行路径/沙箱路径）并入沙箱详情。
```

### 文案表（工作台，替换现有 S 键的展示文案；键名不变，值改）

| 现文案 | 改为 |
| --- | --- |
| 「校验在评分度量跑，模型改满试、超时置整不生效…」 | 「校验只看沙箱里当前的代码，和对话过程无关。跑一次约 1-5 分钟，同一轮可以反复跑。」 |
| 「当前轮提示词可以直接发送给内置模型；复制按钮仅用于导出或外部备用用…」 | 删除整段，功能并入提示词卡的两个按钮 |
| 接线说明区块 | 折叠块标题「用外部模型跑？」，内容一句话+复制按钮：「复制提示词，到模型官网的对话里粘贴使用；回来后把改动同步进沙箱即可。」 |
| 「沙箱是受测仓库的独立副本，模型只能在这个目录里改动。清空改动只重置沙箱，不动任何评测记录。」 | 「沙箱是题目的独立工作副本，模型只在里面改代码。」 |
| 跳转到/提示词/对话/沙箱/校验/本轮 | 由步骤条取代（① 对话改代码 ② 运行校验 ③ 结果与下一轮） |
| 基线哈希/沙箱路径/运行ID（题头） | 全部移入沙箱详情折叠 |

### 交互硬要求
- 空态（还没对话/还没校验）保留，但每个空态直接给主 CTA（现状已有，别丢）。
- 校验完成后若用户在对话卡：toast 提醒「校验完成：通过 12/16」并聚焦校验卡（结果提醒）。
- 全部折叠件用 `<details>`/button+aria-expanded，键盘可达；动效只允许 opacity/max-height 150ms。
- 轮询驱动的一切状态变化必须同时更新步骤条（②③ 的完成态）。

### 信息架构
```
[页头] 模型档案 + 一句话说明（现说明可保留精简）+ [新增档案]（唯一强调按钮）
[档案卡列表] 每张卡两行：
  行1：模型名（主字）· 服务商徽标（OpenAI 兼容/Anthropic 等按 protocol）· 密钥状态chip（已存密钥✓/未配置）
  行2：base_url（mono，一行截断，title 悬停全文）
  动作（行1右侧，幽灵按钮组）：[测试连接] [编辑] [删除]（删除必须 confirmDialog，文案说明连跑分记录的处理）
  卡上直接显示上次测试结果（有则显示：✓ 4项全过 · 刚刚 / ✗ 连不上：超时）
[编辑/新增] 用 openModal 弹表单（现有 modal 组件），字段：
  1. 模型名称*（就是现在的 model 字段，明说"调用时填的模型名"）
  2. 接口地址*（base_url，placeholder https://api.example.com/v1，帮助一行：一般以 /v1 结尾）
  3. API 密钥（password 输入；说明一行：保存在这台电脑上，不会进 git/配置文件；留空=不修改已存密钥）
  4. 档案编号（id，新增时自动生成可改，编辑时只读）
  5. 高级（折叠）：协议 protocol、接口形态 api_mode、key_env 环境变量名——默认全部收起
  表单动作：[保存]（强调）[取消]；保存后自动触发一次测试连接并把结果标在卡上。
```

### 改造点
1. **档位筛选改分段控件**（全部/初级/中级/高级/王者五个 chip，单选），原生 `<select>` 删除。搜索框保留但用现有输入样式，不裸奔。
2. **档位视觉分级**（用官方色板值，暗色下降低饱和、只上 chip 底和卡片顶部 2px 发丝线）：
   初级=mineral `#629987`，中级=pencil `#f0ac54`，高级=kraft `#d4a27f`，王者=plum `#827dbd`。
   徽标文案：`初级 · 试 1 次` / `中级 · 试 2 次` / `高级 · 试 3 次` / `王者 · 试 3 次`。
3. **卡片层次**：标题衬线加大一级（阅读主角）；题目一句话摘要保留；「目标通过率 60%~85%」这类校准元数据弱化成脚注小字或收进详情——**用户 first 眼要读的是这题考什么**（考察：…）。
4. 卡片 hover 抬升只允许边框变亮 + 150ms，禁止阴影扩散；「进入工作台」改 ghost，整卡可点进工作台。
5. 首启三步引导（若在 views.css 旧段里）样式迁到新文件，逻辑不动。
