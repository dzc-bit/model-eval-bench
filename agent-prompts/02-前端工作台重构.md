# 任务：前端重构——以对话流为核心的工作台

你是前端重构负责人。这个仓库是一个本地模型评测台，前端在 `console/static/`（原生 ES module，
零构建、零第三方依赖，改完刷新即生效）。当前前端功能全但**太乱**：工作台按钮一大堆、操作路径长、
工具调用和总结展示得不好。你的任务是参照市面上主流的 agent harness 前端（Claude Code、
ChatGPT、Cursor、OpenHands 这一类），把前端——**尤其是工作台**——重做成「聊天框为主」的形态。

## 开工前必读（按顺序）

2. `README.md` §5 —— 控制台功能全貌（工作台、批量跑批、记分板等各视图干什么）。

## 重构方向（目标态）

### 工作台 = 聊天框为主

- **对话流是页面的主轴**，占据视觉中心。用户消息、模型回复、工具调用、思考摘要、
  校验结果，全部按时间顺序落在同一条对话流里（主流 harness 都是这么做的）。
- **工具调用**渲染成对话流里的紧凑卡片：一行摘要（工具名 + 关键参数，如文件路径/命令），
  默认折叠，点开看完整入参出参；成功/失败有明确的色彩与图标区分。现在平铺占屏的展示方式是
  要解决的问题之一。
- **模型思考（reasoning）**默认折叠成一行「已思考 xx 秒 / 点击查看」，不抢正文的视觉权重。
- **校验报告**作为对话流里的一个结果节点内联展示（现在是内联的，保持），分组红绿、
  失败摘要做得更清楚；校验后有明确的「下一步」引导。
- 页面其余元素让位：状态（哪个题、哪个模型、第几轮、沙箱状态）压缩成顶部一条细状态栏。

### 简化操作路径，砍按钮

- 每个时刻只有**一个主按钮**（按状态机切换：发送 → 校验 → 继续/结束），其余操作收进
  次级菜单或设置区。现在的按钮数量要明显降下来。
- 从「选题目」到「开始对话」的步骤数要缩短，能默认的默认、能记忆的记忆。
- 但注意下面红线第 1 条：简化 ≠ 把路藏没。

### 已拍板的两项变更（直接做）

- **模型档案删除补上级联入口**：删除档案时提供「连同其下运行记录一起删除」选项，
  默认不勾选；勾选后调 `DELETE /api/models?id=…&with_runs=1`，文案必须写清「不可恢复」，
  确认时列出将删除的记录数。
- **记分板统计口径修复**：`trials` 分母只计真实跑过的轮次（剔除建了记录但从未进入评分流程的），
  同一档案多次尝试的均分口径与排行榜对齐（「记分板与排行榜必须同口径」是既有红线）。
  涉及后端统计代码的改动在交付说明里单列，并给出前后数字对比。

### 其他视图顺手收敛

记分板、排行榜、任务库、批量跑批、模型档案、设置、帮助：不动信息架构，但统一视觉语言
（按钮层级、间距、色彩都走 `tokens.css` 的令牌），明显啰嗦的操作路径顺手简化。

## 前端红线（用户逐条定过的，逐字遵守）

1. **出口不许条件隐藏**：每个状态都要把「能走的路」全摆出来。可以收进次级菜单让界面干净，
   但任何状态下用户都必须能找到全部可用出口；不可用的给禁用态 + 原因写在按钮上，
   **不是消失**。简化按钮数量和这条不冲突：收进菜单可以，删到找不到不行。
2. 必须保留**显式的「结束本轮并回收沙箱」**，不能只留折叠起来的回收。
3. 最终总结内联在对话流里，不做弹窗、不做 sticky；历史区不 sticky 悬浮。
4. 回基线（重建沙箱）必须作废旧成绩，旧错误列表必须跟着消失。
5. 只有网络调用进 `try`：删除已落盘成功、收尾步骤出岔子不能报成「删除失败」。
6. 地址栏是书签：记录被删后要把 `run_id` 段摘掉。
7. 删除语义三个动作（作废本轮成绩 / 结束本轮 / 废弃本轮）各有分工，别合并、别改名，
   文案含义见 `AGENTS.md` 删除语义表。

## 两个真实踩过的 JS 坑

- `createWorkspace(props)` 里解构出来的 `const` 绑定运行期不能改，需要改的值复制成 `let`，
  否则抛 `TypeError` 并把一次成功的删除误报成失败。
- `node --check x.js` 对 ESM 语法**静默返回 0**，等于没查。校验前端语法必须复制成 `.mjs`
  再 `node --check`，或 `node --input-type=module --check`。

## 工程约束

- 保持零构建、零第三方依赖、原生 ES module。不引入框架、不引入打包器。
- 样式集中走 `console/static/css/tokens.css` 的令牌，不发明新色值。
- `workspace.js` 目前约 58KB，借这次重构拆分，单一文件不要超过它能被一个人读完的体量。
- 后端 API 尽量不改；确实需要后端配合（比如为对话流补一个字段）可以改 `console/`，
  但要在交付说明里单独列出。
