## #0 重点项：收敛「结束」语义——一个出口，彻底结束（用户拍板，最高优先级）

问题：工作台收尾出口太多、功能重叠（作废/结束/废弃三连，用户分不清）。
用户拍板的新模型，逐条照做：

1. **校验跑完后选「结束本轮」= 彻底结束**：先把本轮成绩写入一个**独立的 results 台账**
   （`runs/` 下的持久文件，与运行记录脱钩——这是关键设计：记录删了之后榜单还有数），
   然后**真删**整条运行记录（记录目录 + 沙箱 + 评分树，走现有 `delete_run`/`purge_run`
   路径），工作台回到干净空态，下次再跑是全新一轮。
2. **记分板/排行榜改从台账读数**，不再从 `runs/` 记录现算；**以最高得分记录**——
   同一题×同一模型，台账保留每次结束的成绩条目，榜单展示最高分那条
   （通过率/Wilson 区间等口径随之简化；被淘汰的旧口径在文档里说明）。
3. **「废弃本轮（真删）」保留但语义收窄**：不进台账、不留痕的彻底抹除——
   跑错了不想让这次进榜时用。它与「结束本轮」的唯一区别就是进不进台账。
4. **「作废本轮成绩（继续对话）」原样保留**：它是继续路径不是收尾出口，不动；
   作废轮与判无效轮永不进台账。
5. **模型档案删除 = 彻底删除**：删档案即连同名下运行记录与台账条目一起真删，
   记分板/排行榜上该模型随之消失。现在删除确认框里的级联勾选项**去掉**，
   确认文案改成「连同 N 条记录一并删除，不可恢复」（默认即级联，不再有勾选项）。
6. **一次性回填**：把现有 `runs/` 里的在册记录按新口径生成台账条目（作废/无效轮不进），
   回填后榜单数字必须与现状一致（本机现有：T1-01/T1-02 100、T1-03 0、T2-05 83.3）。
7. 「清空改动」「重建沙箱」是轮内动作不是收尾出口，保留；dock 与 ⋯ 菜单按新语义收敛，
   出口仍全列、禁用带原因（红线不变）；「结束本轮」保持显式常驻。
8. 文案同步：`AGENTS.md` 的删除语义表、README §5、帮助页、strings.js 里相关措辞
   全部改写到新模型（旧三连的描述一处不留）。

验证：新增测试锁定——结束时台账写入+记录真删、榜单取最高分、废弃不进台账、
档案删除连台账一起清、作废/无效轮不进台账；回填后榜单数字与回填前一致；
浏览器走完整生命周期（跑→校验→结束→工作台空态→榜单有分→再跑一次低分→榜单仍取最高）。

## 该修（三项）

### #1 点击超时诊断（原问题 5）

症状：工作台/档案页里 Playwright 原生 `click()` 对快照里真实存在的按钮频繁超时
（「删除」「查看排行榜」都中过），而 `evaluate(el.click())` 能成。
先诊断后修：在问题页面用 3 秒、每 250ms 一次采样记录目标按钮的 `getBoundingClientRect()`——
位置一直在变 = 有轮询在反复重排 DOM（布局抖动），找到抖动源修掉；位置稳定就
`elementFromPoint` 查按钮中心实际命中的元素，命中别的 = 有透明层在收事件，修掉它
（大概率是某个常驻层缺 `pointer-events: none` 或轮询重渲染）。
验收：修复后同一个按钮用原生 click 连点三次都成功。

### #2 新机 clone 首次启动路径（原问题 13）

仓库已公开，这是所有新用户的第一步。在临时目录真 clone 一次仓库，启动服务，浏览器走一遍：
健康检查全红时页面说什么、有没有指引去编辑 `console/config.json`、任务库空态长什么样、
帮助页能不能接住一个完全没配过的人。把断了的地方补上（文案或引导），目标是一个新人
不看 README 也能在页面上被领到「改 config.json 的 repo_root」这一步。

### #3 揭晓的参考解要落盘（原问题 8）【与 runs.py 冲突时跳过】

现在「查看参考解」只在当次把补丁下发给前端，刷新就没了。改为：揭晓时把参考补丁写到
run 目录（如 `revealed.patch`），报告窗与复盘都从运行记录读。已有揭晓标记的语义不变。
注意删除纪律：`purge_run` 的真删范围本来就含 run 目录，不用特判。

## 可修（六项）

### #4 供应商视图直接下发 run_count（原问题 9）【与 runs.py 冲突时跳过】

删除供应商前的级联计数，现在是前端复刻后端匹配逻辑（前缀+legacy_ids），两份必然漂移。
改为后端在 `/api/providers` 的供应商视图里直接下发 `run_count`（用 `delete_provider`
同一份匹配逻辑计算，只读无副作用），前端 models.js 删掉复刻版直接用该字段。

### #5 200% 缩放与窄屏实测（原问题 12）

帮助页声称「200% 不破版」，grid 外壳换成视口锁定后没实测过。浏览器里把视口调到
375px 宽、再把页面缩放到 200%，八个视图各走一遍。破了就修（CSS 走 tokens 令牌），
不破就在 `console/harness/VALIDATION.md` 记一笔「2026-10-02 实测通过」。

### #6 报告窗内的新结果提示（原问题 6）

报告窗是打开时刻的快照。开窗期间该 run 有了更新报告时，在窗口顶部出现一条
「有新结果，点击刷新」（polite，不抢焦点、不自动替换内容）。没有更新就不出现。

### #7 揭晓自动弹窗写进文档（原问题 7）

「查看参考解」成功后自动打开报告窗是已定行为。在帮助页「怎么读校验结果」一节补一句说明，
让用户预期到它。只加一句，别展开。

### #8 思考时长是估算的说明（原问题 10）【与 strings.js 冲突时跳过】

帮助页或对话流思考行的展开态里补一句：「思考时长按相邻消息时间估算；接口不返回推理时
该行不显示。」让用户对空的思考行有预期。

### #9 工具行长会话性能留档（原问题 11）

不改代码。在 `console/harness/NOTES.md` 的已知限制里记一笔：折叠工具行的内部 pre
保持完整布局，超 200 次调用的长会话如观察到卡顿，候选方案是虚拟滚动。
