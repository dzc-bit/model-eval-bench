# 任务：校验全部题目包的真实难度与评判标准

你是题目质量审计员。这个仓库是一个本地模型评测台（出题侧），题库在 `packs/core/tasks/` 下，
共 11 道题（T1-01 ~ T4-11）。你的任务是**逐题体检**，回答两个问题：

1. 这道题的真实难度和它宣称的档位（T1 初级 / T2 中级 / T3 高级 / T4 王者）是否匹配？
2. 它的评判标准（隐藏用例、分组权重、提示词分级、越界边界）有没有问题？

## 开工前必读（按顺序）

1. `AGENTS.md` —— 项目维护纪律，尤其是「时间与统计口径」「验证门禁」两节。
2. `README.md` —— 项目全貌，重点看 §1（四档难度定义）、§5（可改边界与越界判定）、
   §6（入库门槛）、§9（校准纪律）、§10（当前题库状态表）、§11（已知遗留）。
3. `设计文档.md` —— 规则源头，重点看难度四杠杆、§6.5 出题清单、计分语义。
4. `packs/core/README.md` —— 出题纪律。
5. `packs/core/index.json` —— 题目登记表。

## 体检方法

对每道题，至少做这几件事：

- **通读题面包**：`meta.json`、`prompts/1.md~3.md`、`inject/patches/`、`hidden/`（含
  `groups.json`）、`p2p.json`、`reference/fix.patch`、`reference/partial.patch`、
  `reference/notes.md`。对照设计文档 §6.5 逐条核。
- **难度判断**：注入的问题是否「考查找而不是考排障+设计」？陷阱和诱饵是否真实有效？
  提示词三级解锁的信息量梯度是否合理（第 1 级会不会泄露太多 / 第 3 级是不是直接报答案）？
  半成品解的得分（见 README §10 表格）落在合理区间吗？这档位的硬性规格（模块数、隐藏组数、
  陷阱数等）达标吗？
- **评判标准审查**：`groups.json` 权重分配合理吗（coherence 权重最高的原则守住了吗）？
  隐藏用例是否只断言形态与取值、不断言锚解私有命名？有没有「答案在明面上」的泄露
  （守卫测试名、文档点名不变量）？p2p 白名单覆盖够吗？`allowed_paths` 范围合理吗？
  有没有可能出现「模型做对了但判错 / 做错了但判对」的路径？
- **工具复算**：用 `packs/core/tools/packcheck.py` 和 `runs/blind/tools/packgate.py`
  复算门禁（用法见 README §6、§12），确认 README §10 状态表是否还属实。
