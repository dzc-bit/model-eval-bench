# T1-01 参考解说明

> 本文件**只进 `reference/`**，永远不进沙箱快照白名单（§4.2 答案隔离）。
> 它是出题侧的存档：锚解为什么这么写、陷阱在哪、§6.5 逐条怎么打勾。

## 一、锚解的形态：抽共享点，接通四个调用方

§6.3 对初级题的硬性规格是"**修复 = 抽共享点并接通 ≥2 个调用方**"。本题的锚解落点在
`backend/astock_backtester/models.py`——它是唯一同时被根层与数据层允许依赖的模块
（`tests/test_architecture.py` 的 `ROOT_MODULES_ALLOWED_IN_DATA = {"models"}`），
且不引入任何新模块，不碰依赖方向。

新增三样东西：

| 符号 | 作用 |
| --- | --- |
| `TURNOVER_RATE_PERCENT` | 采集侧写入换手率时乘的倍数。**读侧折算的分母必须和它严格相等**，这是一条可反推验证的闭环。 |
| `UNKNOWN_NUMERIC` | "未知"的表示。写侧用它，读侧靠空值自然落选。 |
| `turnover_rate_to_fraction()` | 唯一的折算实现，同时接受标量与 `Series`，让两套调用路径**在结构上不可能各自演化**。 |

接通点（四个，≥2 的要求是超额满足）：

1. `data/astock_adapter.py::_apply_turnover_rate` —— 派生时用 `TURNOVER_RATE_PERCENT` 而不是字面量 `100.0`；补值改成"只补空缺"；`fillna(0.0)` 整条删除。
2. `data/astock_adapter.py::_with_derived_columns` —— 用 `UNKNOWN_NUMERIC` 显式置空。
3. `data/astock_adapter.py::_apply_market_cap` —— 恢复"只补空缺"，不再用今日股本覆盖历史逐日值。
4. `data/importer.py::normalize_daily_bars` —— 缺列默认值从 `0.0` 改为 `UNKNOWN_NUMERIC`。**这一处在原始仓库里就已经是错的**（不是注入的），见第五节。
5. `conditions.py::_turnover_ratio` —— 折算改为无条件，函数体整个委托给 `turnover_rate_to_fraction`；`_mask_turnover_between` 改回调用它。
6. `engine.py::_stock_limit_pct` —— 恢复"先定板块，再叠加风险警示收紧"。

## 二、注入态的四个静默点

| # | 位置 | 注入内容 | 症状 |
| --- | --- | --- | --- |
| 1 | 采集派生 | `fillna(0.0)` 兜底 | 推不出的行变成"换手率 0%"，参与打分 |
| 2 | 采集补值 | 整窗覆盖 | 增发/解禁过的票，历史市值被今天的股本放大 |
| 3 | 条件两注册 | 行级"看数值大小猜量纲" + 预筛不折算 | 两条路径结论相反，预筛把对的票提前丢掉 |
| 4 | 引擎 | 先判风险警示再判板块 | 高限制板块的风险警示票被按 5% 拦掉 |

四个都不报错、不抛异常、量级仍然合理——这是"静默"的定义。

**为什么不是回滚历史修复**（§4.2 第 3 层、相似度 < 0.6）：注入不是把某段代码改回原样，
而是把"共享口径就地内联 / 去掉空值保护 / 调换判定顺序 / 加一层看似合理的兜底"四种
重构型改写重新做了一遍，注释与 docstring 也一并改写过。仓库里 `git log` 能查到的历史
修复是"抽出共享常量"和"删掉 0 兜底"这两件事，本注入是它们的镜像，且注释措辞完全不同，
相似度远低于 0.6。

## 三、陷阱

### 陷阱 A：只修两个出口中的一个（`reference/partial.patch` 演示的就是它）

用户描述的症状是"策略一个候选都选不出来"，最顺手的下手是去修**预筛**（那才是把票丢掉
的那一步）。但 prefilter 只是执行者，量纲判错的是逐行判断。两个口径只要有一个没接上，
结论仍然相反。

`partial.patch` 演示的是反向版本：只把逐行判断改对（去掉猜量纲），预筛仍然直接拿采集列
比较。结果：

- `condition_row_exit` 绿（权重 1）
- `condition_mask_exit` 红
- `coherence` **红**（权重 2）——行级说通过、预筛说全否
- 实测得分 **14.29 / 100**

只修一个端口必然 < 100 由这一条保证。

### 陷阱 B：四个"看似可疑但实际正确"的点

改这道题的模型大概率会去动下面几处。**它们都是对的**，动它们不会让任何组转绿，
只会引入新的不一致：

1. **另一条行情通道里按当天股本反推市值的写法**（`volume / (turnover / 100) * close`）。
   长得像"重复换算了量纲"，但它算的正是**那一天**的市值，是全流程里最准的一版。
   真正的 bug 是用最新股本把这一版覆盖掉。
2. **实时快照通道里 `亿 → 元` 的单位换算**。长得像"又一处量纲不一致"，但它换的是
   通道自身声明的单位（`float_mcap_yi`），语义正确。
3. **规模条件绑的是流通市值而不是总市值**。名字相近，但"小盘"按流通口径筛是产品定义。
4. **市值中性打分里"市值 <= 0 时退回中位数"**。看着像掩盖坏数据的兜底，其实是刻意的
   中性处理：坏数据不应该获得极端打分。

### 陷阱 C：把未知兜底成 0（第 2、3 级提示词里都点名否决了）

这条是最容易复现的错误修法：把所有空值填 0，"让下游比较不报错"。它换来的不报错是假的
——`turnover_column_exit` 组会红，而且打分排序被永久污染。

## 四、§6.5 反过易检查清单（逐条打勾）

- [x] **grep / 读文档 / git log 找不到"该修哪里、改成什么"。**
  三处注入点附近的注释与 docstring 在 `inject_edits.py` 里被同步改写过，原始那句
  "缺列默认值是 0.0，不置空就会写成换手率 0%"的自述被整段抹掉；`classify` 类的口径
  说明也一并抹平。仓库文档没有对应条目，`git log` 里没有可对照的提交。
- [x] **≥1 个"看似可疑但实际正确"的诱饵点。**
  四个，见上节陷阱 B。其中 1 和 2 是纯代码诱饵（不 grep 就撞上），3 和 4 要读到才会动。
- [x] **每组隐藏测试有第二数据场景，硬编码 / 特判必挂。**
  - `turnover_column_exit`：3 条，其中"多日窗口"与"外部帧缺列"是两个不同入口；
  - `market_cap_column_exit`：2 条，一条单日、一条双日（一天有值一天无值）；
  - `condition_row_exit` / `condition_mask_exit`：各 2 条，阈值带（0.2%~0.8% vs 1%~20%、
    2%~8% vs 0.5%~5%）与取值集合都不同，且每条内部都跨过量纲分界（≤1 与 >1 两侧都有）；
  - `limit_board_exit`：4 个高限制板块代码 + 1 个主板对照组，后者专门防"一律不收紧"和
    "一律 5%"两种极端解；
  - `coherence`：2 条，两条不同的跨出口组合。
- [x] **症状与三级提示词不含任何文件 / 函数 / 常量名。**
  三级提示词全篇只使用业务词汇（换手率、流通市值、风险警示、涨停）。`packcheck.py`
  会对 `prompts/*.md` 做标识符形态扫描，命中即失败。
- [x] **只修一个端口的半成品必然 < 100 分。**
  `partial.patch` 实测 14.29。
- [x] **出题者自评"我 10 分钟能一次做对"→ 退回重做。**
  自评结论：**超过 10 分钟**。理由——第一次定位到"行级与预筛给出相反结论"这一层就已经要
  读两条调用路径；再往下的量纲归属、覆盖语义、判定顺序三件事没有任何一条能从症状直接推出来，
  必须靠数据反推（写侧乘 100 ⇒ 读侧除 100），而这一步需要先意识到"写侧倍数"是可观测的。
  落盘代码涉及 5 个文件、97 行增删。

## 五、两处需要单独说明的设计

### 5.1 第四处口径不是注入的，是仓库本来就有的

`data/importer.py` 的缺列默认值是 `0.0`，而采集链路对同一个未知值是留空。这两处口径相反
是**原始仓库就存在的**（注入补丁没碰这个文件，`0001~0003` 三个 patch 的路径里没有它）。

把它留在题目里有两个理由：一是它天然满足 §4.2 第 3 层——模型无法用"回滚某个历史提交"解决
这道题，因为根本没有那个提交；二是它让"把口径收到一处"这件事成为**必需**而不是可选：
只改采集侧不改归一化侧，`turnover_column_exit` 组照样红。

代价是：这条断言在**基线态就是红的**。这是刻意的——它属于目标组，不是 p2p。

### 5.2 快照里本就红的用例

`p2p.json` 只收基线全绿的既有用例。快照里有 7 条在**基线态就是红的**，已全部剔除：

| 用例 | 状态 |
| --- | --- |
| `test_core.py::test_a_share_trade_dates_excludes_2015_to_2023_holidays` | 基线红（依赖交易日历表，与本任务无关） |
| `test_core.py::test_a_share_trade_dates_excludes_2027_and_2028_holidays` | 同上 |
| `test_core.py::test_a_share_trade_dates_keeps_adjacent_trade_days` | 同上 |
| `test_architecture.py::test_no_layer_below_the_service_imports_it_back_up` | 基线红（层级白名单与快照不匹配） |
| `test_engine.py::test_stock_limit_pct_follows_board_before_st` | 基线红 + 名字直接点名判定顺序 |
| `test_engine.py::test_limit_up_block_uses_board_specific_thresholds` | 基线红 + 名字点名板块 |
| `test_engine.py::test_limit_down_block_uses_board_specific_thresholds` | 基线红 + 名字点名板块 |

后三条同时进了 `visible.prune`：它们既红又点名答案，留着等于把第 1 题白送。
