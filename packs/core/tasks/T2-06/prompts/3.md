必须同时成立的表述：

1. **同分区的写入必须互斥，且互斥必须在操作系统层面成立。** 进程内的锁对象管不到另一个进程；"哨兵文件存在"也不是互斥——两个进程可以同时观察到它不存在、同时创建、同时进入临界区。文件锁（字节区间锁定）或等价的 OS 原语才是合格答案。锁的持有者必须是进程崩溃时能被操作系统自动释放的东西。
2. **分区文件对读者只有两种合法状态：完整的旧内容，或完整的新内容。** 落盘必须走"同目录临时文件 + 原子替换"（或等价机制），替换是原子的、不可分割的观察点；写失败的任何时刻，盘上仍必须是写之前的完整内容，临时文件要清理。
3. **"文件不存在"与"文件存在但读不出来"是两个语义，读侧必须区分。** 前者是"还没有数据"，返回空表；后者是损坏，必须把原始错误原样抛出、并把分区路径连同错误登记进损坏清单——不允许吞成空表，也不允许在缺列、行组裁剪等其它路径上把两类混同。
4. **健康口径必须由损坏清单驱动。** 诊断输出里要有分区级的损坏明细（路径 + 错误）与总体健康位；没有损坏登记时报健康、报空明细。覆盖数、读侧、健康三处对同一年分区的答案必须互相印证——不允许出现"读侧当缺失、健康报正常"或"覆盖数归零却说不出为什么"的组合。

已被否决的思路（不要重提）：

- "把锁超时从 120 秒改小（比如 1 秒）"——超时抛错是**正确行为**：它意味着互斥真的在排队。改小只会让正常的大分区写入更频繁地被误判成超时，互斥本身一点没变。
- "把损坏分区当空表返回，让上层无感知地继续"——这正是病灶本身。缓存文件坏了可以回源重抓，数据仓分区没有回源；空表把"坏"伪装成"没写"，补数循环从此空转，而且每一轮都不报错。
- "在诊断接口上按画像端点自己的成败来定健康"——端点算完画像 ≠ 分区都是好的。健康位必须来自损坏登记，否则"分区坏了"这件事永远到不了页面上。

仓库里有一批守着写入互斥与损坏暴露的既有用例，它们的名字和说明把上面这些不变量写得很直白。你不需要去改测试、也不需要以"让某条既有用例变绿"为目标——评测用的是一套独立的、你们看不到的用例，其中并发相关的用例是真的用两个进程跑的。

## 必须同时成立的不变量

1. 写入互斥：判定标准是"两个独立进程同时写同一个年份时，后到者要么排队等待、要么明确失败，绝不会与先到者并行进入写入区"，而不是"应用内部各加一把只在本进程里有效的锁"。
2. 换入原子：判定标准是"任何时刻从盘上读到的内容，要么是旧的完整内容、要么是新的完整内容"，而不是"大多数时候不会读到一半"。
3. 失败不毁旧：判定标准是"写入过程在任何一步失败之后，盘上仍然是写之前的完整内容，中间产物被清理干净"，而不是"失败后留下一个需要人工收拾的现场"。
4. 损坏与缺失分流：判定标准是"文件本来就不存在时返回空、文件存在却读不出来时必须报错并把原始原因带出来"，而不是"两类都返回空表"。
5. 健康由损坏登记驱动：判定标准是"有登记就报不健康、并列出是哪个年份、什么错误；没有登记才报健康且明细为空"，而不是"由某个诊断入口自己算完一遍就宣布健康"。
6. 三处口径互证：判定标准是"读侧、覆盖率、健康提示对同一个年份的结论必须一致，任何一处说坏、另两处就不能说是空的"，而不是"三处各自算各自的"。
7. 补数不空转：判定标准是"损坏的年份不会被当成还没采集而进入重新抓取、重新写回的循环"，而不是"循环跑完看不出任何异常"。

## 已被否决的思路（这些方向试过，不要再提）

1. "让读取方读到半截内容时自己重试几次"——重试只是把撞上半截的概率压低，写入方仍然是先清空再逐块写，撞上就是撞上；而且读取方不知道该重试多久才算完。
2. "限制成同一时刻只允许一个进程写入"——两个写入方并存是既定场景，禁掉等于砍功能；要的是它们共存而不互相破坏。
3. "写失败之后干脆把目标内容删掉，等下一次补数重写"——把"丢了新内容"换成"连旧内容一起丢"，对账的时候缺口只会更大。
4. "在页面上多显示一行'可能有问题'的提示，后端照旧"——提示没有权威来源支撑，覆盖率照旧归零，坏消息并没有真正被暴露出来。
5. "把有问题的年份从统计里剔掉，眼不见为净"——缺口被人为抹平，页面看着健康，对账时才发现少了一大块。
