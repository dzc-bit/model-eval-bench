# T4-11 出题存档（王者压轴题）

> 本文只进 `reference/`，永不进入沙箱。题目处于草稿门禁状态前，不得对外宣称已校准或保证所有模型三轮必败。

## 一、出题目标与事实边界

这道组合题把两条已经独立成题的真实故障链放在同一评分任务中：实时行情的并发仲裁/迟到发布/降级轮询，以及数据写入的批次、跨进程互斥、缓存新鲜度与健康刷新。它要求模型在三轮累计修改中同时恢复两条链路，并满足额外的跨子系统 coherence 组。

**已确认事实**：已有 T3-09 与 T3-10 各自的锚解均能令各自隐藏组全绿；两套注入补丁目标文件不冲突。组合锚解是两份参考修复的并集，组合半成品只恢复实时 single-flight 和写入脚本攒批，因此覆盖范围明显小于完整题。

**合理推测**：六个可改文件、13 个 pytest 计分组、1 个 Vitest 计分组、283 条 p2p 回归白名单（280 pytest + 3 Vitest）、跨进程时序与前后端行为耦合，会显著增加三轮内完整修复难度。

**未验证假设**：强模型连续三轮仍不能修完。确定性评分与公开的三级提示词无法从逻辑上保证任何能力等级的模型必败；必须用非出题模型的 pass@3 盲测验证。作者不填造校准记录。

目标为非出题模型 `pass_at_3` 落在 `[0.0, 0.02]`。若样本不支持这个目标，应重新设计题目并重跑盲测，不得把“王者”标签当成证据。

## 二、任务范围与四类耦合不变量

| 边界 | 必须共同满足的行为 | 评分组 |
| --- | --- | --- |
| 实时 worker 生命周期与发布授权 | 超时不提前释放 single-flight；已取消/已超时的后台工作不能写共享诊断或行 | `single_flight_exit`、`late_publish_exit` |
| 实时快照顺序与界面探活 | 版本/代际决定权威顺序；旧结果不回退；部分成功降级重试 | `generation_exit`、`chain_budget_exit`、vitest `frontend_degrade_exit` |
| 分区并发写入与统计新鲜度 | 互斥内重读、合并、原子替换；跨进程行守恒；写入立刻失效派生缓存 | `cross_process_exit`、`freshness_exit`、`amplification_exit` |
| 写入可见性与跨层对账 | 有界锁重试；健康刷新如实；脚本汇总、盘面、统计和健康口径一致 | `lock_retry_exit`、`health_exit`、`coherence_write`、`coherence` |

联合 `coherence` 组将实时仲裁交错场景与写入后健康覆盖场景放在同一组里：两条链中任一条仍旧失真，不能获得该组权重。完整分数还要求所有分组和两侧 p2p 白名单均绿。

## 三、注入与锚解

本题复用现有合成注入补丁，并按唯一顺序编号：

1. `0001-realtime-arbitration.patch`：移除后台生命周期绑定、迟到发布栅栏及权威世代仲裁。
2. `0002-frontend-market-degrade.patch`：移除部分成功降级轮询与成功时点单调守卫。
3. `0003-run-full-market-import.patch`：让脚本逐票写盘并使用分区内存旧快照覆盖。
4. `0004-warehouse.patch`：写入后只清一项缓存，其他统计等待 TTL。
5. `0005-service.patch`：健康请求不触发或报告后台覆盖刷新。
6. `0006-operations.patch`：锁争用重试降为单次尝试。

`fix.patch` 是 T3-09 与 T3-10 的已验证修复并集，覆盖全部六个 allowed 文件。它不改变隐藏测试、依赖配置或 checker。
`partial.patch` 只恢复实时 single-flight 的后台释放边界与脚本批量写入；它故意没有修复迟到发布、代际仲裁、前端降级、仓储缓存与并发互斥、锁重试及健康刷新，应低于满分。

## 四、陷阱与诱饵

- 只修“旧快照回跳”而不处理迟到 worker 的写权限，`late_publish_exit` 和 single-flight 相关场景仍失败。
- 只修实时后端、不修前端降级周期，vitest 组仍失败；反过来只做前端时间戳过滤也无法令服务端 generation 与迟到发布组变绿。
- 只把写入批大小调大，显式指定批大小的隐藏场景仍会发现逐票落盘与放大；并且跨进程覆盖与统计缓存没有修复。
- 让 `/health` 同步全量扫描，不能满足快速返回与刷新中状态的约束。
- `scripts/backfill-market-cap.py` 的按年分区整行写回是诱饵；该路径使用不同的正确分区协议，不应被本题顺手改动。

## 五、脱敏、裁剪与白名单

- `visible.prune` 合并 T3-09 的实时仲裁答案路标与 T3-10 的缓存失效、锁重试、健康刷新及攒批答案路标。裁剪条目均从 p2p 白名单剔除。
- Python 侧 p2p 是两题现有白名单的并集，Vitest 侧 p2p 沿用实时题的 3 条既有用例。任一回归红都让该轮记 0 分。
- `redactions` 合并原两题对 `AGENTS.md` 和 `CHANGELOG.md` 的脱敏要求。提示词只使用业务症状和状态不变量，不写文件、函数、常量名。
