# 前端调试坑记录 · 2026-10-01 UI 改版

本轮 UI 改版（Claude 风格 + 三视图重构 + 侧栏 + 帮助页）踩到的坑，按「症状 → 真因 → 教训」记。
每条都值得回看：它们共同的特征是**本地检查通过、用户实际使用才暴露**。

---

## 一、三个模块语法错误，整页卡在「正在载入界面」

**症状**：页面永远停在静态占位文字，侧栏都不出现。浏览器控制台能看到 `Illegal return statement`。

**真因**：解决 git 冲突时留下的三处残骸——
| 文件 | 残骸 | 后果 |
| --- | --- | --- |
| `chat-panel.js` | 删冲突块时多留一个 `}`，函数提前闭合 | 顶层 `return` → 模块解析失败 |
| `grade-panel.js` | 两侧各留一份 `const currentAttempt` 声明 | 重复声明 → 模块解析失败 |
| `run-bar.js` | 删方法后残留孤立 `}` | 同上 |

**关键教训**：`node --check` **按 CommonJS 解析**，抓不到这些错误——
- 顶层 `return` 在 CommonJS 里合法
- 重复 `const` 在非严格模式下不报

**正确检查方式**：
```bash
node --input-type=module --check < file.js   # 真正的 ESM 语义
```
合并冲突后必须对**所有** JS 跑一遍 ESM 检查。

## 二、TDZ：变量在声明前使用

**症状**：任务库整页报「页面没能正常启动」，其他视图正常。

**真因**：`calibBanner` 在第 445 行声明，却在第 233 行的 DOM 组装里被引用。
`const` 有暂时性死区，声明前访问直接抛 `ReferenceError`。

**为什么难发现**：`node --check` 和 ESM 语法检查都**只做语法解析、不做执行**，
TDZ 是运行时错误。只有真的调用 `createTaskLibrary()` 才会触发。

**排查手段**：浏览器里动态 import 模块并调用，捕获真实异常：
```js
import('/js/views/task-library.js').then(m => {
  try { m.createTaskLibrary({navigate(){}}); } catch (e) { document.title = String(e); }
});
```

## 三、外壳在宽屏下塌陷（最隐蔽的一个）

**症状**：用户在 2000px 超宽屏上看到帮助页正文竖排、页脚跑到页面顶部。

**真因**：`.app-shell` 用 `flex-wrap` 表达四种角色（通栏状态条 / 侧栏 / 主栏 / 通栏页脚），
`#status-host` 和 `.app-footer` 都靠 `width: 100%` 抢整行：
1. 状态条先占满第一行 → header 被挤到第二行
2. main 和 footer 挤在第三行互相分空间 → 主栏只剩 558px

**为什么我反复测不出来**：我一直在 1440px 下测，那时总宽不够、footer 被挤到下一行，
**反而看起来正常**。宽屏才暴露。

**修法**：改用 CSS Grid 命名区域，把布局意图直接写出来，不依赖元素顺序与宽度博弈：
```css
grid-template-areas: "status status" "header main" "header footer";
```

**关键教训**：**测试必须覆盖用户的真实屏幕尺寸**。多档宽度（2560/1920/1440/1100/860/500）
逐个验证，而不是测一个就下结论。

## 四、IntersectionObserver 不触发

**症状**：帮助页目录的「当前章节」高亮，滚动时纹丝不动。

**排查过程**（三轮才找到）：
1. 先怀疑 root 不对 → 改成 `.app-main` → 还是不触发
2. 手动测 `scrollIntoView` → 发现 `scrollY` 恒为 0，**页面根本没滚动**
3. 实测 `.app-main` 的 `overflow-y: visible`、`scrollHeight === clientHeight`
   → **它根本不是滚动容器**，页面是文档滚动

**真因**：我按 `a11y.js` 的注释假设 `.app-main` 是内部滚动容器，实际不是。
给 observer 指定错误的 `root` 后，回调一次都不触发。

**修法**：`root` 保持默认（视口），用 `window.scrollTo` 验证。

**关键教训**：**注释会过时，实测不会**。滚动容器这种事必须用
`getComputedStyle().overflowY` + `scrollHeight/clientHeight` 实测确认，
不能读注释或猜。

## 五、多栏网格把阅读顺序搞乱

**症状**：帮助页「歪了」——第 4 节在右上、第 3 节在左下。

**真因**：主列用了 `grid-template-columns: repeat(auto-fill, minmax(340px, 1fr))`。
章节高度差大时，CSS Grid 按行填充，短章节并排、长章节单独占位，
**视觉顺序与文档顺序脱钩**。

**修法**：正文改回单栏阅读流（`max-width: 76ch`），只有术语表这种
**等宽短条目**才在自己的小节里用多栏。

**关键教训**：多栏网格适合**同质、等宽**的内容（卡片、术语表），
不适合**长文正文**——正文的顺序就是它的意义。

## 六、判断「谁是对的」：`copy_tree` 语义

**症状**：合并时两个测试断言互相矛盾——
一条期望 `overlay_dest_rel == "frontend/src"`，另一条按实际搬运结果期望
`frontend/src/tests_hidden_fe`。

**判断依据**：读 `util.copy_tree(src, dst)` 的实现——它把 `src` 的**内容**
复制到 `dst`，所以 `dst` 必须是**完整目的地路径**（含最后一级目录名）。
后者正确。

**关键教训**：两个断言打架时，去读**被调用函数的真实语义**，
而不是猜哪个"看起来更合理"。顺带发现原代码 `prefix == "src"` 的判断
永远为假（真实题包写的是 `hidden-fe/tests_hidden_fe`），
那个修复从未生效过。
