# 模型评测台 · Model Eval Bench

把"给模型出一道**真实的代码排障题**"这件事工程化：合成注入、沙箱隔离、分组部分分、
三级提示词、入库门禁、校准纪律，全部落成可执行的代码与可入库的任务包。

- 设计与验收标准：[`设计文档.md`](设计文档.md)（v2.2，含四层隔离、难度四杠杆、十一道起步题、任务包规范）
- 任务包出题指南：[`packs/core/README.md`](packs/core/README.md)（流水线 8 步、工具速查、删除纪律）
- 历次审计与整理账本：[`runs/audit/`](runs/audit/)（按日期归档；最新一次见 `runs/audit/2026-10-02/`）

> **先读这一句**：本题库的定性是**公开样例**（2026-10-02 拍板）——本仓库已在 GitHub 公开，
> `packs/core/tasks/*/reference/`（锚解、半成品解、注入点说明）与 `packs/core/tasks/*/hidden/`
> （对被测模型隐藏的评分用例）连同题目本身都随仓库公开，作为引擎能力与出题规范的样例存在
> （`packs/demo/tasks/DEMO-01` 是同一性质的演示题）。「隐藏」从此只指**对被测模型不可见**
> （沙箱快照不含、提示词不泄露），不指对公众保密。完整声明与严肃评测的私有题库指引见
> [§8 公开样例声明](#8-公开样例声明重要)。

## 1. 它解决什么问题

给模型出题最容易出的三种废题（设计文档 §6.1 列为禁止项）：**答案在明面上**（守卫测试名/文档
直接点名不变量）、**本质是回滚历史修复**（`git revert` 就完事）、**单点注入单点变红**
（考的是查找而不是排障+设计）。这个评测台用题目隔离、文件夹工作区、合成注入和独立评分树控制评测流程：

| 层 | 手段 |
| --- | --- |
| 1 · 内容隔离 | 沙箱快照只拷运行测试必需的子树；相关文档段（`AGENTS.md`/`CHANGELOG.md`）进 `meta.redactions`；点名不变量的守卫用例进 `meta.visible.prune` |
| 2 · 工作区约束 | 沙箱位于评测台的普通文件夹中；内置对话通过受限工具操作该目录 |
| 3 · 版本隔离 | 沙箱内 `git init` + 单提交 `baseline`；注入是**合成改写**（与历史修复相似度 < 0.6） |
| 4 · 评分隔离 | 评分树 = 原始快照（测试已裁剪）+ overlay（只收 `allowed_paths` 内产物）+ 隐藏层，**不在沙箱里跑** |

这套隔离的对手是**被测模型**，不是公众：本题库连同答案与隐藏用例已定性为**公开样例**（§8），
「隔离」「脱敏」「隐藏」防的都是模型顺手看答案、抄历史修复；对访客，这一切都直接可读。

难度分四档（§6.3）：初级 T1（1 次尝试）/ 中级 T2（2 次）/ 高级 T3 与王者 T4（各 3 次），硬性规格逐档加码
（≥4 模块、必须自行设计机制、≥2 陷阱、≥5 隐藏组、含并发或性能硬约束）。计分是**按组加权
部分分**，`coherence` 组权重最高（只断言"多出口对同一事实口径一致"），`p2p` 回归组权重 0
但一断即本轮作废。

```

├─ 启动.cmd                    ← 双击即起服务并打开浏览器
├─ console/                    ← 评测台本体（纯标准库，零构建）
│  ├─ server.py                ← HTTP 服务 + JSON API + 静态托管
│  ├─ config.json              ← 唯一配置（受测仓库/路径/超时/快照白名单/模型档案）
│  ├─ harness/                 ← 通用校验引擎：sandbox / snapshot / grade / runs / report / packs / batch / selfcheck
│  │  └─ tests/                ← 引擎自身的用例与自造题包 fixture（数量见最新验收记录）
│  └─ static/                  ← 前端（原生 ES 模块，无构建、无第三方依赖）
│     ├─ js/views/             ← 八个视图：任务库 / 排行榜 / 工作台 / 批量跑批 / 记分板 / 模型档案 / 设置 / 帮助
│     └─ js/components/        ← 17 个组件（含 result-mark 成功失败 SVG 动画）
├─ packs/                      ← 题库与答案（公开样例），**永不进沙箱**
│  └─ core/
│     ├─ index.json            ← 题目登记表（status / target_band / prune / p2p / 门禁摘要）
│     ├─ README.md             ← 出题指南（流水线、工具、删除纪律）
│     ├─ tools/                ← 出题侧自验工具（纯标准库）
│     └─ tasks/T1-01 … T4-11/  ← 十一道起步题
├─ runs/                       ← 运行记录、出题侧脚本与历次审计报告
│  ├─ blind/tools/             ← 门禁 runner、盲测编排、整理工具（成题脚本存档在 tools/archive/）
│  ├─ blind/gates/             ← 门禁临时评分树落点（跑完自动删，不入库）
│  ├─ blind/calib/             ← 盲测试跑记录
│  └─ audit/<日期>/            ← 历次审计 / 整理 / 重构报告
└─ sandboxes/                  ← 沙箱落点 + 快照缓存 + 跑批快照（内容不入库）
   ├─ .snapshots/              ← 按题缓存的"已注入基线骨架"
   └─ _batches/                ← 批量跑批的批次快照（batch.json，服务重启后可查）
```

单个任务包（`packs/core/tasks/<ID>/`）：

```

prompts/1.md 2.md 3.md     ← 三级提示词：症状 → 不一致清单 → 不变量 + 否决项（零文件名/函数名/常量名）
inject/patches/NNNN-*.patch← 合成注入（标准 unified diff，按文件名顺序应用）
hidden/tests_hidden/*.py   ← 隐藏评分用例（评分时才出现）
hidden/groups.json         ← 分组与权重（coherence 权重最高；p2p 权重 0 + mode=regression）
                             用例 ID 相对 hidden/ 那层写（`tests_hidden/x.py::t`），
                             引擎会自动补成相对评分树根的路径
p2p.json                   ← 必须保持全绿的既有用例白名单（ID 相对评分树根写：`tests/x.py::t`）
reference/fix.patch        ← 锚解（相对注入态，须拿 100 分）
reference/partial.patch    ← 半成品解（只修一个端口，须 < 100）
reference/notes.md         ← 出题侧全账：注入点、陷阱与诱饵、裁剪理由、§6.5 逐条打勾、门禁结果
calibration/results.json   ← 校准总表（盲测前保持空表）
calibration/gate_*.json    ← 三级门禁原始输出
```

## 3. 环境要求

| 项 | 要求 | 本机实测 |
| --- | --- | --- |
| Python | 3.11 ~ 3.13 | 3.13.1 |
| pytest | ≥ 8.2（**评测台自己不用**，是给受测仓库跑用例的） | 9.0.3 |
| Node.js | 仅**前端题**需要（`slim-py+fe` 快照）；优先用受测仓库自带的 `.tools/node-*`，否则系统 PATH | 可用 |
| 第三方依赖 | **评测台本体零依赖**（纯标准库）；受测仓库自己的依赖由它自己的 venv 提供 | — |

不需要 `pip install` 任何东西就能启动控制台；跑门禁时才需要目标仓库的依赖可导入。

> **解释器纪律**：评分子进程用的是「启动服务的那个 Python」（`checks/pytest.py` 走
> `sys.executable -m pytest`）。隐藏用例要 import 受测仓库的依赖（pandas / numpy /
> pyarrow / duckdb / akshare / pydantic / openai …），所以正确做法是在评测台根建一个
> `.venv-gate`（已被 `.gitignore` 排除）把这些依赖装上——`启动.cmd` 检测到它就优先用，
> 否则退回系统 `python` 并给出警告。直接双击启动前请先确认这一点，否则校验会在收集阶段
> 全灭、分数直接是 0。

## 4. 快速开始

```powershell
# 1) 改唯一一行配置：受测仓库在哪
#    console/config.json → "repo_root": "D:\\New project 6"
#    （其余路径都是相对评测台根目录的，换机器不用改）

# 2) 启动（二选一）
双击  启动.cmd
python console\server.py --open          # 等价写法；--port / --host 可覆盖 config.json

# 3) 打开前端
http://127.0.0.1:8899
```

启动后控制台会做一次环境自检（受测仓库可读、pytest/Node 可用、文件夹沙箱可用、静态资源完整），
异常项直接显示在页面上。API 入口：`GET /api/tasks`、`GET /api/tasks/<ID>`、`GET /api/runs`、
`POST /api/batches`（批量跑批）等。

多仓库是可选的：题包 `meta.json` 写了 `repo.id` 时，可以在 `config.json` 里加
`"repos": {"<id>": "<该仓库在本机的路径>"}` 让它单独指仓库，没配的题包回退用 `repo_root`。
这个键填的永远是**你自己机器上的路径**，属本机配置，不要提交进仓库（健康检查会逐个报红，
`repos.<id> 目录不存在`）。

**前端地址：`http://127.0.0.1:8899`**（`host`/`port` 可在 `console/config.json` 改；
前端是零构建的原生 ES 模块，改完刷新即生效，不需要打包步骤）。

## 5. 控制台能做什么

- **任务库**：题目档位、目标带、裁剪条数、白名单条数、历史成绩
- **工作台**（对话流为主轴，一屏三行）：顶部状态栏选档案、看状态，右侧两个图标点开**运行详情**
  与**本轮备注**的小窗口（路径、时长、基线指纹、完整性自检、沙箱操作日志；备注跟着这一轮记录存）；
  中间是可滚动的对话列（滚动条就贴在对话列右边，不是窗口最右端那根），依次是任务与提示词、
  模型回复、工具调用紧凑卡（默认折叠，点开看入参/返回）、内联校验结果条（完整报告在校验窗口/
  报告窗口里）；底部常驻操作栏：每时刻一个主按钮（准备沙箱 → 发送第 n 级提示词 → 运行校验 →
  进入下一轮/揭晓锚解）+ **常驻的「运行校验 / 重新校验」** + 「结束本轮」+「更多操作」菜单。
  输入区只有一颗「发送」（发你打的那句话）；「发送第 n 级提示词」在操作栏，想先改一改再发就用
  「更多操作 → 把当前提示词填进输入框」。
  打开或刷新工作台直接落在**最新一条消息**上；翻历史时右下角出现「↓ 回到最新」。
  点「运行校验」会弹出**校验窗口**：先说清这次在查什么（本题分组口径、权重、回归与越界规则），
  跑的过程中显示进度与实时日志，出分后原地换成结果正文。
  提示词复制仅供导出或外部备用。
- **排行榜**：独立主导航；选择题目后显示该题按模型档案汇总的专属排行（同一模型展示最高分那次）。
- **批量跑批**：按 `max_concurrency` 并发准备「多道题 × 多个模型」的会话。
  就绪后进入各自工作台与模型对话，再手动启动校验。**一个条目占一个槽位，直到你在工作台点
  「结束本轮」**——校验出分只是「已出分，等你结束本轮」，队列不会往下派；收尾之后条目按台账
  落定（进台账 / 没留成绩），沙箱随记录一起释放。想提前让出槽位可以在批次页点「跳过（让出槽位）」，
  它不动这条的运行记录与成绩。
  可勾选「自动发送第 1 级提示词」，让沙箱一就绪就把题目发给模型开始作答（默认关闭），校验始终手动。
  取消后不再派发新条目，准备中的任务协作退出；已开始的评分允许收尾（出分即让出槽位）。
  服务重启会带走批次的监控线程：读批次时会按运行记录与台账补齐条目状态、计数与代表分，
  校验完却还占着磁盘的条目上会给「回收沙箱」按钮手动释放（只删沙箱，`runs/` 记录保留）。
- **记分板**：按模型档案分区查看成绩与目标带对比；格子第一眼看「最好一次有没有全绿」，
  `pass@1` 作为稳定性副标一并给出（中级以上题目有 2–3 次机会，第 2 轮才做对也算做对）。
- **模型档案**：必填只有 API 根地址、模型名和密钥——密钥直接在页面粘贴，服务端存到不入库的
  `console/keys.local.json`，`config.json` 与页面只保留脱敏值；协议、调用接口、密钥环境变量名收在「高级选项」。
- **设置**：超时、快照白名单

### 收尾：一个出口就是彻底结束

工作台只有一个收尾出口：**「结束本轮」**（常驻按钮，不折叠）。点它的顺序是
**先把本轮成绩写进成绩台账，再真删整条运行记录**，所以记分板与排行榜在记录消失之后仍然有数，
而工作台回到干净空态——下次再跑这道题是全新一轮。

另两个动作不是它的替代品：

- **「继续对话（本轮分数作废）」**（⋯ 菜单）是**继续路径**，不是收尾出口。误点一次校验时用它：
  本轮标 `voided`，报告挪成 `report-discarded-*.json` 留在原地当证据，沙箱与模型已做的改动全保留。
- **「废弃本轮（真删，不留成绩）」**（⋯ 菜单）用于**跑错了不想让这次进榜**。它与「结束本轮」的
  磁盘后果完全一样（记录、对话、报告、diff、沙箱、评分树全删），**唯一区别是进不进台账**。

成绩台账是 `runs/_results/ledger.json`，与运行记录脱钩。每次「结束本轮」留一条条目，
记分板与排行榜展示**最高分那条**。作废轮、越界/回归判无效的轮次，以及已揭晓参考解的尝试，
**永不进台账**。所以旧口径里的 Wilson 置信区间随之一并废弃——条目不再等于「通过的样本」，
在一行样本上算区间只是假精确。

帮助页（左栏「帮助」）另有一节**题目现象速查**：每道题的现象、注入的根因、这一轮校验盯哪几个
出口、正确的修复方向，跑之前先看一遍就知道这道题在考什么（不写参考解代码，也不列隐藏用例文件名）。

从旧版本升级时做一次性回填（幂等，不删任何记录）：

```bash
python -c "import sys;sys.path.insert(0,'console');from harness import runs,config;print(runs.backfill_ledger(config.load()))"
```

**删除模型档案 = 彻底删除**：档案、已存密钥、名下运行记录与台账条目一起真删，
记分板与排行榜上该模型随之消失。确认框里没有勾选项（默认即级联），会写明「连同 N 条记录
一并删除，不可恢复」。正在对话或校验的记录会跳过并在结果里说明。

### 对话中的模型思考

接口返回的文本 `reasoning_content` 或 `reasoning` 会在对话流里显示为默认折叠的「模型思考（n 字）」一行，
点开看全文，并随 `chat.jsonl` 保存；刷新后仍可查看。工具调用前的推理字段按原名保留，供后续 API 回合使用
（DeepSeek 一类服务商在请求携带 `tools` 时要求历史轮完整回传，不回传会直接报错）。
接口没有返回推理时不再显示“未返回可展示的推理内容”这类占位语，正文本身就是全部内容。
长请求期间轮询已落盘的模型/工具消息；当前是逐回合刷新，不是逐 token 流式输出。
这取决于服务商公开字段，不保证取得完整隐藏思维链。

### 发送与超时：一条消息「收下即返回」

`POST /api/runs/{id}/chat` 只做参数校验和登记，随即返回回执，模型那一轮跑在服务的后台线程里。
因此**没有任何一层需要为对话留超时**：一轮对话可以连跑几十次工具调用与模型请求（实测二十分钟、
四百多条记录），旧的同步等待只会让前端先到期、弹一个像失败的错，而服务端其实还在跑。

- 页面刷新或关掉都不会中断这一轮；重新进入工作台时按 `chat_busy` 自动接回，继续轮询到结束。
- 上一条还在处理时再点发送会被挡下并给出提示，草稿留在输入框里不丢——避免同一轮里塞进重复追问。
- 意外中断会在 `chat.jsonl` 里留下一条错误记录，不会静默消失。
- `config.json` 的 `timeouts.chat_s`（默认 600 秒）只管**单次模型调用**的网络超时；整轮对话不设时限，
  工具轮数也不设上限，这是评测口径的一部分。

### 对话的上下文窗口与压缩（`config.json` 的 `chat` 节）

发给模型的上下文由服务端按「完整轮次」组装，与前端展示的完整记录是两套视图：
`chat.jsonl` 与工作台始终是全量，只有送给模型的那一份会被压缩或裁剪。

```json
"chat": {
  "max_history": 100,        // 单位：条。历史消息条数上限，按完整 user→assistant/tool 轮次累积
  "max_context_chars": 160000,  // 单位：字符。上下文字符预算（含压缩后的历史），与条数是双闸门
  "tool_summary_chars": 800, // 单位：字符。历史轮工具返回压成摘要后保留的字符数
  "keep_first_prompt": true  // 是否始终保留第一条用户消息（题目提示词）
}
```

超预算时的处理顺序是**先压缩、再丢弃**：历史轮的工具返回换成「工具名 + 参数 + 结果摘要」
（`write_file` 保留路径与字节数，正文已落盘不必重发）→ 仍超就把更老的轮次塌成「只剩模型说过的话」
（调用清单同样带 `write_file` 的路径与字符数）→ 再超才整轮丢弃，且钉住的第一条提示词与最新一轮
不参与丢弃 → 最新一轮自己超预算时，先在它内部降级（组首 user 与最近一段原文钉住，中间工具往返
摘要化），仍超才原样发出。真发生整轮丢弃时会在 system 消息里写明「更早的 N 轮对话已省略」；
省略行会带上「其间写入过：<文件清单>」——这是模型对「自己改过哪些文件」的最后记忆，不能只剩省略号。
这样修掉了旧实现里「受测模型一轮并行 6 个工具调用、消息数超过
`max_history` 就把整轮裁掉，续轮只能靠 git 重新考古」的失忆问题。

**压缩不等到轮边界才发生**：单轮工具循环进行中，每次请求前都会把上下文压到预算的八成以内
（上下文到预算 80% 即触发降级）——实测受测模型单轮就能跑出 100+ 条消息、百万级字符，等下一轮
再压就晚了。单轮内降级只改内容、不增删消息，工具调用与结果的配对不会破坏；早期 assistant 的
思维链在单轮内截断保留前缀（字段仍在，跨轮历史组装仍按服务商口径原样回传）。
这些值是默认项，`config.json` 只写其中几项也能生效；窗口数字写坏会退回默认值，不会让对话不可用。
窗口是**全局**的：换到上下文更小的模型时，正确动作是把 `max_context_chars` 调小，
而不是等它报窗口超限。压缩会重写历史，服务商侧的前缀缓存因此必然失效——这是有意的取舍，
「续轮不失忆」比省这点 token 更重要。

服务商返回**空消息不等于收束**：content 为空且没有工具调用时，先原样重试一次，仍空就报错落盘
（带 `finish_reason`）——实测有中转在长上下文下返回空响应，静默当收束会让任务没完成就停，
用户被迫手动发「继续」。模型档案配了 `max_tokens` 时请求会带上它：不传这个字段时不少服务商按
自己的小默认截断输出，思维链把额度吃满、正文返回空。错误落盘时一并写入脱敏后的 `detail`
（超时 / 连接被重置 / TLS 失败在文案上是同一句话，没有 detail 就无法事后归因）。
工具的安全限制（沙箱路径、命令白名单、超时、输出上限）不受这些配置影响，只可能更严。

### 可改边界与越界判定

每道题在 `meta.json` 里声明 `allowed_paths`。内置对话的 system 消息会**逐轮把这份清单告诉模型**
（「本轮只允许修改这些文件…清单之外的文件可以读，但只要发生改动，本轮就直接判无效」）——
题面按脱敏纪律不能出现文件名，所以边界由操作规程告知，不靠模型事后猜。

校验时的判定：

| 越界情形 | 结果 |
| --- | --- |
| 改了 `allowed_paths` 之外的文件（含语句、新增、删除） | 记违规，本轮作废判 0，`raw_score` 仍保留 |
| 越界文件里**只改了注释或空行** | 记为提示，不作废（这些文件本就不进评分树，不该抹掉其余正确改动） |
| `__pycache__`、`.log` 等运行产物 | 记为提示，不影响判分 |

隐藏用例只断言**形态与取值**，不断言锚解新起的字段名：模型把信息放进别的字段名或提示文案里同样算对，
但注入态必须仍然查不到该信息，判别力不丢（纪律见 `packs/core/README.md` 第二节第 6 条）。

### 校验的两道护栏

- **模型没动手时不许校验**：对话里还没有任何 assistant 回复时，「校验」按钮禁用并写明原因，接口同样以 400 拒绝。
  刚建好沙箱就点校验，只会按「未改动」判 0，白烧一次尝试机会。这条门槛放在接口层而不是评分引擎里——
  出题侧与引擎测试是用"直接往沙箱写文件"模拟模型改动的，它们不经过对话。
- **误校验可以补救**：校验区的「继续对话（本轮分数作废）」会把本轮标为 `voided`、状态退回 `ready`，
  沙箱与模型已做的改动全部保留。作废的分数不进台账，模型改完后重新校验会记作新一轮结果；
  已经揭晓参考解的轮次不开这个口子。

「查看参考解」成功后会自动打开报告窗，参考解就在里面；参考解正文同时存进运行记录的
`revealed.patch`，刷新页面后仍可回看。它会把这一轮标记为「已揭晓」——该轮成绩**永不进台账**。

模型档案需要有效的 `base_url`、服务商支持的模型名和 API 密钥。密钥在「模型档案」页直接粘贴，
服务端保存到本机密钥文件 `console/keys.local.json`（已被 `.gitignore` 排除），立即生效、无需重启；
页面与 `config.json` 只保存脱敏值，明文不回显。也可以改用服务端环境变量提供密钥，
优先级：页面粘贴的密钥 → `key_env` 指定的变量 → `MODEL_<档案ID大写>_API_KEY` → `OPENAI_API_KEY`。

当前工作区是普通文件夹，并非操作系统级容器。文件与命令工具会限制路径、命令种类、超时、环境变量和输出量；沙箱内运行的程序仍可能利用自身能力访问本机其它资源。不要把它用于不可信代码的强安全隔离。

## 8. 公开样例声明（重要）

**定性（2026-10-02 拍板）**：本仓库已在 GitHub 公开，`packs/core/tasks/*/reference/`（锚解、
半成品解、注入点说明）与 `packs/core/tasks/*/hidden/`（评分用例）事实上已经公开。接受这个
现实，正式把题库（含答案与隐藏用例）定性为**公开样例**，废止「本仓库公开 = 题目作废」的
旧口径。

1. **公开样例存在的意义**：作为引擎能力与出题规范的样例——完整展示题目包格式、三级提示词、
   合成注入、分组计分、门禁与校准纪律一路长什么样；`packs/demo/tasks/DEMO-01` 是同一性质的
   演示题。样例题可以练手、可以读规范，但不再承担「保密考题」的职能。
2. **「隐藏」的新含义**：从此只指**对被测模型不可见**——沙箱快照白名单不含它们、三级提示词
   不泄露它们的存在与内容；不再指对公众保密。下述 4~6 条红线全部保留，因为它们防的始终是
   模型作弊（四层隔离见设计文档 §4.2），不是防公众看。
3. **做严肃评测必须另起私有题库**：样例题的锚解与用例已公开，谁都能背答案；成绩要进任何
   **对外对比**，就必须用一套同样格式、不公开的私有题库来跑。操作指引：
   - 按 [`packs/core/README.md`](packs/core/README.md) 第一节的目录规范，在本仓库之外、
     不进公开仓库的位置建一套私有题包（结构同 `packs/core`，`<私有根>/<题包名>/tasks/<ID>/`）；
   - 把 `console/config.json` 的 `"packs_root"` 从 `"packs"` 改指私有根——该字段是引擎扫题的
     唯一入口（`console/harness/packs.py` 逐个子目录找 `tasks/<ID>`；`packs/demo` 这个第二
     题包就是同样挂进来的）；
   - 引擎与前端零改动，题包是 drop-in 的（设计文档 §17）。
4. `packs/`、`reference/`、`hidden/` **永不进沙箱快照白名单**；`allowed_paths` 不得指向它们。
5. 症状与三级提示词**不得出现任何文件名 / 函数名 / 常量名**——`packcheck.py` 会把
   `allowed_paths` 叶子名、隐藏测试标识符与用例名、分组 id、注入与参考解里被改的文件名
   汇成禁用词表，对三级提示词做大小写不敏感的全词扫描，命中即红。
6. 注入必须是**合成改写**（与历史修复相似度 < 0.6），不做"把历史修复反向打回去"。
7. 受测仓库（`repo_root` 指向的项目）是**独立仓库**，不在本仓库内，也请勿把它拷进来。

> 难度校准与盲测纪律（§9）不受本声明影响：题目公开影响的是保密性，不影响难度校准；
> `calibrated` 仍以非出题模型盲测为准。

## 9. 校准纪律（硬规则）

**出题者不做盲测校准。** `calibration/results.json` 在盲测完成前保持空表
（`blind_runs.rows: []`、`summary` 全 `null`），`calibrated` 恒为 `false`，meta 与 results
两处一致；`packcheck` 会拦截任何"作者自填校准数据"的形态。盲测由后续组织的**非出题模型**
实例完成：T1–T3 每个样本只给第 1 级提示词，记录 pass@1；王者每个样本在同一沙箱中
逐轮校验并最多解锁三级提示，记录 pass@3 与 `rounds_used`。同一会话的提示轮不拆成独立样本，
并记录 Wilson 95% 置信区间（弱模型测下界 + 强模型测上界）。

### 已修的真实缺陷

**（2026-09-30）四个「不报错、只是结果错」的读侧缺陷** —— 详见
[`console/harness/NOTES.md`](console/harness/NOTES.md) 第四节。它们此前一直没被发现，
因为都是"静默走偏"而不是抛错：

1. **注入补丁读错目录**：真实题包的补丁在 `inject/patches/`，代码只读 `patches/`
   → 返回空 → 题目在**未注入的干净代码**上评测（`injected: 0`）。
2. **隐藏用例少了 `hidden/` 前缀**：`groups.json` 写 `tests_hidden/x.py::t`，
   评分树里的真实路径是 `hidden/tests_hidden/x.py::t` → pytest 收集到 **0 个用例**
   → 147 条 p2p 白名单全部误报为回归 → 每轮强制 0 分。
3. **裁剪切坏源文件**：多行装饰器（`@pytest.mark.parametrize(...)`）只删了函数体、
   留下悬空装饰器 → 文件语法错误 → 整批用例收集失败。
4. **`git apply` 静默假成功**：骨架目录还没有自己的 `.git`，`git -C` 向上找到评测台
   自己的仓库 → git 打印 `Skipped patch` 但**退出码仍是 0** → `injected: 3`
   而一个字符都没改（实测零改动拿 85.7 分）。

修后实测：**注入态 0 分且 6 个目标组全红**、**锚解 6 个组全绿**、p2p 零误报 ——
与 §6 的入库门槛语义一致。

**历史问题（文件夹沙箱迁移后已退役）**：`sandbox.list_subst()` 曾按错码页解码。原先用
`GetConsoleOutputCP()` 当 `subst` 输出的码页。`启动.cmd` 会先 `chcp 65001`，此后该 API
返回 65001，而 `subst.exe` 写到管道时仍按 ANSI 码页（简中 936）编码 —— 中文名沙箱的路径
被解成乱码，越界检测误报「盘符指向别处，请重建沙箱」，连带 20 条引擎用例变红。当时改为
**ANSI → OEM → UTF-8 → GBK** 候选码页逐个 strict 解码。细节见
[`console/harness/NOTES.md`](console/harness/NOTES.md) 第四节。

> **排障提示**：若接口"时好时坏 / 偶发 500"，先确认 8899 端口上是不是**并存了两个服务实例**。
> Windows 的 `SO_REUSEADDR` 允许两个进程都 `LISTEN` 成功，请求会被随机分流到新旧两套代码：
> `netstat -ano | findstr :8899` 应当只有一个 LISTENING 的 pid。
