## 2026-10-02 收尾语义与响应式实测

### 「结束本轮」台账链路（浏览器 + 真实 API）

| 场景 | 实际结果 |
| --- | --- |
| 回填后榜单数字 | 与回填前逐格一致：T1-01 100 / T1-02 100 / T1-03 0 / T2-05 83.3；合计 4 次结束、pass@1 2、通过率 0.5 |
| 有成绩时结束 | `POST /api/runs/{id}/finish` 返回 `ledgered=true`，台账新增一条，记录目录 + 沙箱同时消失 |
| 没成绩时结束 | `ledgered=false`，台账条数不变，记录与沙箱照删（提示「没有可计入台账的成绩」） |
| 真删的父目录收壳 | 记录删空后 `runs/<任务>/<模型>/` 与 `runs/<任务>/` 一并 rmdir，`runs/` 里不留空壳 |
| 两次结束取最高 | 同题同模型先记 30 分再记 100 分 → 单元格 `best_score=100`、`attempts=2`；排行榜只有一行，展示 100 分那条 |
| 废弃不进台账 | `DELETE /api/runs/{id}` 后 `attempts` 不变——与「结束本轮」的唯一区别 |
| 作废轮不进台账 | 点「继续对话（本轮分数作废）」再结束 → `ledgered=false` |
| 出口收敛（浏览器实读） | 底部常驻「结束本轮」+「更多操作」；⋯ 菜单 9 项全部常列，逐项带禁用原因，无一项被隐藏 |
| 记分板渲染（浏览器实读） | 单元格显示「1 次通过 / 共 1 次结束」「最高分 100 · 均分 100」，Wilson 区间已消失 |

### 200% 缩放与窄屏（帮助页声称不破版，这次真测了）

视口锁进 grid 外壳之后一直没实测过。八个视图各走一遍，判据是**页面级横向溢出**
（`document.body.scrollWidth > documentElement.clientWidth`）：

| 视口宽度 | 结果 |
| --- | --- |
| 375px（窄屏） | 八个视图全部 `scrollWidth == clientWidth == 375`，无横向溢出 |
| 640px（1280 宽 200% 缩放后的 CSS 视口） | 八个视图全部 `scrollWidth == clientWidth == 640`，无横向溢出 |

个别元素（`app-header`、帮助页表格 `thead`、跑批的任务选择标签）会超出视口宽度，
但都被各自的滚动容器裁住，不产生页面横向滚动条。**2026-10-02 实测通过。**

### 已知的环境限制（不是本项目的缺陷）

- 本机 in-app 浏览器里 `requestAnimationFrame` 每 2 秒触发 **0 次**（`about:blank` 同样如此），
  Playwright 原生 `click()` 的「连续两帧稳定」检查因此永远等不到，**任何**元素都点不动；
  `evaluate(el.click())` 正常。排查按钮超时问题时先测这条，否则会误判成布局抖动或透明层。
  2026-10-02 的实测结论：位置采样 3 秒只出现 1 个不同坐标（**无抖动**），
  `elementFromPoint` 命中的就是按钮本身（**无透明层**）。
